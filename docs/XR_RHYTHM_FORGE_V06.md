# Domistika XR · Rhythm Forge v0.6

Rhythm Forge extends the existing **Motion Forge** animation preview with a real browser-native, locally chosen music file and opt-in audio analysis. It uses \`AudioContext\`, \`MediaElementAudioSourceNode\` and \`AnalyserNode\`. No third-party audio service, user account, upload, network fetch, recording, microphone or device audio capture.

## First Quest 3 playtest

1. Open [Domistika XR](https://michaelwave369.github.io/Domistika/xr.html) in Meta Quest Browser, **before entering VR**. Pick one or two workshop shapes, and assign a Motion Forge effect such as Pulse, Bob, Spin or Orbit. Creating a Pattern Forge ring and assigning a few different effects makes the reaction easier to see.
2. Under **Rhythm Forge**, press **Choose local track** and select a local MP3, WAV, OGG, M4A, AAC, FLAC or WebM audio file (max 50 MB). The actual supported codec depends on the browser. No track is saved to IndexedDB, localStorage, export JSON or GLB. The file is held as an ephemeral \`blob:\` URL until cleared, replaced or the page is closed.
3. Press **Play track + motion**. This user gesture initializes Web Audio and starts the local file. A bass/energy meter should move. Use the sensitivity slider (0–2×) to control how much music influences the *visual preview*. 0× completely disables the audio influence but the normal procedural Motion Forge effects can still run.
4. Enter VR. The central floating workshop deck now has **RHYTHM PLAY** and **RHYTHM STOP** controls for tracks already chosen in the 2D sidebar. Click with Quest controller triggers. Confirm you can hear the user-provided file and see the motion variation.
5. Press **RHYTHM STOP** or leave VR. The sound pauses, the analyser meter resets, and all editable workshop objects return to their original rest-pose transform. Backgrounding the page also pauses playback. The local track remains selected until the page is refreshed or you clear it.
6. Export workshop JSON: the object positions, appearance, static source labels and bounded Motion Forge descriptions remain. The audio file itself and meter readings are never included. GLB remains a **static rest-pose** export with no media stream, beat tracking or animated GLTF track.

### Exact implementation limits

- Signal: frequency-domain audio spectrum generated by a local \`AnalyserNode\`. Approximate **35–260 Hz bass band** and a broader **up-to-5 kHz** level; a bounded normalized gain modulates the visual effects. **This is not BPM estimation or beat-onset detection.** Low frequencies in music tend to create stronger energy values, which may or may not align precisely with beats.
- No automatic synchronization between a song's musical bar and the time-based Motion Forge effect. Music simply modulates four independently authored, procedural visual modes.
- Effects apply only to editable workshop objects with a Motion Forge effect already assigned. Read-only Framefield BPC animation previews and OpenBlueprint CAD source files are neither modulated nor modified.
- Motion Forge's saved rest transforms remain authoritative. No audio data, file names, temporary URLs or gain values enter \`domistika.xr.workshop.v1\`, undo snapshots, 2D drawing scenes or spatial brush backups.
- The analyser updates during playback only and the meter refreshes about 10 times per second, rather than writing to the DOM every animation frame.
- On Quest, selecting a local file might require leaving immersive mode to use the system file picker. Playback must start from a visible button or VR trigger because browsers restrict autoplay. Browser codec support, audio routing, and headset performance need **physical Quest acceptance** even after CI passes.
